## Architecture

The consistency chain is:

```
.opencode/skills/{skill}/SKILL.md  ←→  .atl/skill-registry.md  ←→  AGENTS.md
```

Per `.opencode/rules/skill-consistency.md`, any modification to a skill file **must** atomically update all three. No skill modifications should happen in isolation.

The skill-registry is auto-generated by a gentle-pi extension (comment in file header says so), but the compact rules for project skills are currently empty — delegators must load the full skill file.

## Implementation Plan

### Per-Skill Changes Needed

#### 1. `backend-testing/SKILL.md` — Major rewrite

- **Frontmatter**: Convert multiline description to quoted one-liner with trigger words first, ≤250 chars. E.g.: `description: "Backend testing (unit/integration/API): Jest patterns, mock factories, TDD, coverage for NestJS + Prisma."`
- **Body**: Collapse from ~1,500 tokens to 180–450. Extract code examples to `assets/` subfolder. Move verbose reference material to `references/`.
- **Restructure sections**: Activation Contract (when/how to invoke) → Hard Rules (must-haves) → Decision Gates (unit vs integration vs API) → Execution Steps (imperative) → Output Contract (what completion looks like) → References (local links to rules file + assets).
- **Remove external URLs**: Replace Jest/NestJS docs links with local references.

#### 2. `frontend-e2e/SKILL.md` — Major rewrite

- **Frontmatter**: Same one-liner conversion. E.g.: `description: "Frontend E2E testing: Playwright patterns, POM, wait strategies, API mocking for Next.js + React 19."`
- **Body**: Collapse from ~1,870 tokens to 180–450. Extract Playwright config, code examples to `assets/`. Move best practices to `references/`.
- **Restructure sections**: Same 7-section layout.
- **Remove external URLs**: Replace Playwright docs links with local references.

#### 3. `prisma-orm/SKILL.md` — Full rebuild

- **Frontmatter**: Add complete YAML frontmatter block (missing entirely).
- **Language**: Translate body from Spanish to English (per project conventions).
- **Body**: Collapse from ~913 tokens to 180–450. Focus on imperative instructions: schema edit → migrate → generate → verify. Extract troubleshooting table and command reference to `references/`.
- **Restructure sections**: Full 7-section layout from scratch.

#### 4. `ticket-workflow/SKILL.md` — Extreme compression

- **Frontmatter**: Quoted one-liner, ≤250 chars, trigger words first. Current description is ~280 chars. E.g.: `description: "Ticket workflow: Trello selection → branch → SDD → test → judge → commit → PR → verify → handoff."`
- **Body**: This is the hardest. Current ~4,488 tokens must compress to ≤1,000 (hard max), ideally 180–450. This skill currently contains the entire project pipeline documentation.
- **Strategy**: Extract phases, checklists, and command references into `references/` supporting files. Keep only the imperative flow skeleton and hard gates in `SKILL.md`. The skill body should be a concise decision flowchart + mandatory gates, not a full reference manual.
- **Restructure sections**: Activation Contract → Hard Rules (branch-first, runtime gate, no-commit-without-tests) → Decision Gates (which package, SDD or skip) → Execution Steps (one-liner per phase) → Output Contract (PR created + Trello updated) → References (link to extracted phase docs).

### Conflicts to Preserve

1. **Trigger words**: Each skill's description must retain the trigger phrases that the orchestrator uses to match skills. Don't change semantic triggers, just reposition them to the front.
2. **Local reference paths**: All `.opencode/rules/*.md` and `.opencode/skills/*.md` paths must remain valid after restructuring.
3. **AGENTS.md skills table**: Already correct; no changes needed unless skill names change (they won't).
4. **Skill-registry auto-generation comment**: The file header says it's auto-generated by gentle-pi. Manual edits may be overwritten on next `/skill-registry:refresh`. Consider whether to populate compact rules in the registry or rely on the orchestrator loading full skill files.
5. **prisma-orm Spanish content**: Translating to English changes the skill's character. Ensure domain-specific Spanish terms that agents might need (e.g., seed data references) are preserved as evidence, not translated away.
6. **ticket-workflow phase detail**: This skill is the project's most critical workflow. Extreme compression risks losing mandatory gates. The extracted `references/` files must be loadable by agents, and the SKILL.md must link to them explicitly so the orchestrator knows to load supporting docs when delegating.
